# 터미널 plugin 인수 기준

[English](acceptance.md)

이 plugin은 터미널 그림 영역의 이 기준을 담는다. core는 [표면 합성](https://github.com/soksak-app/core/blob/main/docs/spec/surface-composition.ko.md#인수-기준)의 일반 기준을 유지한다.

- 터미널 그림은 리사이즈 중 논리 텍스트를 보존한다. 폭을 줄이면 열 수를 줄여 긴 논리 행을 여러 화면 행으로 재배치하고, 폭을 늘리면 열 수를 늘려 잘림이나 좁은 상태의 영구 고착 없이 다시 재배치한다.
- 터미널 셀 너비와 높이는 배치 중에도 고정된 표시 메트릭이다. 디바이더 이동은 표면·래스터 기하만 바꾸고 글꼴이나 셀 메트릭을 바꾸지 않으며, 네이티브 기하 변경은 애니메이션하지 않는다.

- terminal view의 primary pointer 누름은 shared exposure binder를 통해 선언된 `terminal.focus` command를 실행한다. command는 native image region으로 keyboard 소유권을 넘긴다. view는 기본 DOM focus를 막고, focus 실패를 `terminal.session`과 surface 오류 경로로 보고하며, page를 dispose할 때 binding을 제거한다. 별도 view document는 main document의 card로 pointer가 bubble되는 데 의존하지 않는다.
- callback을 보고하는 native input scope는 `{type:'input', actions, preedit, errors, cids}` region event 하나로 온다. `cids`에는 scope correlation identifier 하나가 있다. 순서가 보존된 `actions`는 확정 insert `{type:'insert', text, replacementRange, attributed}`, key `{type:'key', key, shift, alt, ctrl, text?}`, command `{type:'command', selector}`, focus `{type:'focus', focused}` record다. Key action은 `key`가 `Char`일 때만 string `text`를 가지며 다른 key는 이 field를 생략한다. Focus의 `focused`는 boolean이다. `errors`는 순서가 보존된 `{reason}` record 목록이다. 필수 strict `preedit` object는 `text`, `markedRange`, `selectedRange`, `replacementRange`, `attributed`를 포함하며 빈 `text`는 preedit을 지운다. Compose-only report에는 빈 action list도 유효하다. 별도 scope의 `insertText`와 `setMarkedText` callback은 각각 한 input scope를 만들며 callback을 보고하지 않은 keyDown은 event를 만들지 않는다. VT `input` request는 같은 순서의 action과 최종 snapshot을 담은 `{actions, preedit}`다. Paste와 `terminal.input`은 현재 strict preedit을 포함한 insert action 하나를 보낸다. Terminal은 status나 sidecar를 변경하기 전에 native event 전체와 모든 action을 검증한 뒤 VT `input` request 하나를 시도하고 `cids`는 body가 아닌 request correlation metadata로 전달한다. 최종 snapshot은 `terminal.compose`에 한 번 적용한다. Request 시도 뒤에는 전송이 실패해도 유효한 event error를 순서대로 보고하고 전송 실패도 보고한다. Event error는 VT action이 아니다. 잘못된 event는 status update나 VT request를 만들지 않는다. `native-input` diagnostic entry의 `input` projection은 정확히 `{actions, preedit, errors}`를 담고 event kind와 `cids`는 별도 field다. `terminal-input` entry에는 정확한 VT request body와 `cids`가 있다. 중첩 callback용 기록은 만들지 않는다. Terminal은 중첩된 `insert`, `key`, `command` 또는 중간 `compose` callback을 각각 소비하지 않으며 text로 compose 전환을 추측하거나 다음 callback을 기다리지 않는다. VT sidecar는 action과 최종 preedit을 하나의 surface input command에서 적용하며 해당 transaction의 중간 compose-only frame을 제출하지 않는다.
- `terminal.ime.trace`는 bounded native-input 및 terminal-input entry만 기록하며 screen frame을 보관하지 않는다. Performance trace가 켜져 있으면 기존 `plugin.terminal.sidecar.event` trace가 event-size 한도 안에서 screen cells, frame tuple, cursor/preedit, render metadata를 포함한 수신 sidecar body를 기록한다. 수락한 각 `screen` message의 DEBUG `plugin.terminal.frame` event는 비동기 hash 전에 캡처한 정확한 native frame tuple 또는 `null`을 message의 session, segment, sequence, 크기 및 screen hash와 함께 기록한다. Native frame tuple은 message를 만든 raster를 식별하며 message sequence만으로는 native frame을 고유하게 식별할 수 없다. Consumer는 session, segment, message sequence로 body와 수락 marker를 결합한 뒤 둘의 frame tuple이 같은지 확인한다. Body가 없거나 잘렸거나 해당 구간에 `log.dropped`, `log.gated`, `log.pruned` 손실 기록이 있으면 인접 event 상태를 빌려오지 않고 거부한다. 이 record는 terminal이 수락한 source state만 식별하며 compositor나 display가 frame을 실제 표시했다는 뜻은 아니다.
- Diagnostic build는 현재 view document의 `window.history.length`를 읽는 `terminal.view.history`와 view document content-frame observer를 명시적으로 시작하거나 중지하는 `terminal.view.frames`를 노출한다. Observer는 기본적으로 꺼져 있고 frame history를 보관하지 않는다. 성공한 모든 `start` 응답은 호출 중 같은 view document의 `performance.timeOrigin`과 `performance.now()`에서 새로 읽은 `sourceClock` 및 고정된 WebKit clock-resolution 상한인 `sourceResolutionMs: 1`을 담는다. 반복 `start`는 observer를 재시작하지 않고 anchor를 갱신한다. 이 상한은 메타데이터이며 측정값이 아니다. 각 `plugin.terminal.view.content_frame` trace는 `ResizeObserver`와 다음 animation frame 이후 document root content-box의 width와 height를 document clock의 `resizeAtMs`, `frameTimeMs`와 함께 기록한다. 이 event는 document 크기 갱신을 나타내며 compositor가 해당 크기를 표시했다는 뜻은 아니다.
- 최종 preedit에는 필수 `markedRange` key가 있다. 표시된 text가 없으면 `null`, 있으면 전체 `text`에 상대적인 UTF-16 code unit 기준 `{location, length}`다. Terminal은 이를 `selectedRange`나 `replacementRange`에서 추론하지 않는다. 정확한 값을 `terminal.compose`와 VT input request에 보존하며, 누락·잘못된 형식·text 범위 밖·grapheme을 나누는 값은 status 변경이나 input queue 전에 거부한다. VT screen preedit에도 같은 필수 field와 검증을 적용한다. `selectedRange`는 selection과 caret을 계속 별도로 표현한다.
- `terminal.cursor.frame`은 필수이며 nullable이다. 검증된 `screen` event에서 cursor status는 정확한 `frame`(`null` 또는 `{generation, raster, sequence}`)을 해당 event의 cursor와 `cursor.preedit`에 함께 한 번의 status update로 발행한다. Cursor를 갱신하는 `state` event는 rendered screen pixel을 식별하지 않으므로 `frame`을 `null`로 지운다. State cursor의 `frame`은 생략하거나 `null`이어야 하고, non-null screen frame을 지정할 수 없다. 잘못된 frame은 기존 screen-input 오류 경로를 사용하며 이전 cursor status를 유지한다.
- 각 현재 `screen` message에는 `cursor.caret` key가 필요하다. 현재 target의 raster가 수락되지 않았으면(이미지 없음, sequence 0, dirty/future target 포함) 값은 `null`이고, clean sent frame이면 `{row, col}`이다. 0 이상 정수 좌표는 화면 격자에서 보이는 input-method caret을 식별하며 해당 frame과 같은 `RenderLayout`에서 나온다. 원본 `cursor.row`와 `cursor.col`은 engine 및 replay/hash 의미를 유지하고 terminal은 이를 `caret` 대신 사용하지 않는다. Terminal은 같은 screen event의 cursor, frame, render metadata와 함께 `terminal.cursor.caret`을 발행한다. `state` event는 caret을 `null`로 지우며 native caret을 이동하지 않는다. Key 누락, 잘못된 object 형식, 격자 밖 non-null 좌표는 screen 또는 cursor status를 바꾸기 전에 해당 screen event를 거부한다. Null caret은 native caret을 이동하지 않는다.
- 각 현재 screen event에는 `screen.render`가 필수다. `null`은 renderer가 해당 event와 일치하는 draw를 만들지 않았다는 뜻이며, non-null renderer object는 screen event의 frame과 정확히 일치해야 한다. 필수 field는 `frame`, `pixel`, `grid`, `font`, `underline`, `cursor`, `glyphs`다. `pixel`은 top-left BGRA8 premultiplied sRGB raster의 크기와 stride를 식별한다. `grid`는 integer rows, columns, origin, cell 크기를 식별하고 `font`는 실제 family와 metric을 담는다. `underline.positionFromBaseline`은 CoreText y-up 단위를 사용한다. 각 glyph는 row, column, cell width, 양수 CoreText `fontRuns`, grapheme, effective opaque lowercase sRGB foreground/background, nullable fractional top-left leading-cell-local ink/underline rectangle을 담는다. 이 rect는 leading cell origin을 뺀 raw CTFont/CTLine bounds이며 cell에 clip한 geometry가 아니다. x/y는 음수일 수 있고 cell 또는 glyph span보다 bounds가 더 클 수 있다. 좌표는 finite여야 하고 rectangle width/height는 양수여야 한다. Consumer는 pixel 측정 시 geometry와 raster 교집합을 계산할 수 있지만 선언된 bounds를 다시 쓰면 안 된다. Cursor는 `visible`과 `blinkVisible`이 true이고 shape가 `hidden`이 아닐 때만 그려지며, rectangle은 그 frame에서만 non-null이다. 그려지는 normal cursor에는 effective opaque lowercase sRGB color가 있고, difference-blended cursor의 color는 null이다. 그려지지 않는 cursor는 rectangle과 color가 null이며, blink가 꺼진 visible normal cursor도 여기에 포함된다. Terminal은 `frame`, cursor, preedit과 함께 필수 nullable `terminal.cursor.render`를 한 번의 status update로 발행한다. 누락된 field, 잘못된 값 또는 frame mismatch는 screen/cursor 상태를 변경하기 전에 거부한다. Terminal은 terminal 전용 `render` 확장을 제외한 선언된 screen-message projection을 `screenFromMessage`와 `screenHash`에 전달한다. `state` event는 rendered draw를 지정할 수 없다. Cursor를 갱신하면 `frame`과 `render`를 모두 `null`로 지우고 non-null render를 거부한다.
