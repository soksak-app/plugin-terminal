# Terminal plugin acceptance

[한국어](acceptance.ko.md)

This plugin holds the criteria of terminal image regions. Core keeps the generic criteria of [surface composition](https://github.com/soksak-app/core/blob/main/docs/spec/surface-composition.md#acceptance).

- A terminal image preserves its logical text while resizing: narrowing reduces terminal columns and reflows long logical rows onto multiple screen rows; widening increases columns and reflows those rows back without truncation or permanent narrow wrapping.
- Terminal cell width and height are stable presentation metrics during layout; divider movement changes the surface and raster geometry, not the font or cell metrics, and native geometry changes do not animate.

- A primary pointer press on the terminal view runs the declared `terminal.focus` command through the shared exposure binder. The command transfers keyboard ownership to the native image region. The view prevents default DOM focus, reports a failed focus in `terminal.session` and through the surface error path, and removes the binding when the page is disposed. A separate view document does not depend on pointer bubbling to a card in the main document.
- A native insert commits only its text. It does not imply that the remaining input-method preedit ended; a later compose event, including an empty one, owns that state change. A partial commit therefore keeps the current preedit displayed with the committed prefix and sends the insert without first clearing the preedit. The insert does not delete pending native document text.
- A native compose event includes the required `markedRange` key: `null` when no text is marked, or `{location, length}` in UTF-16 code units relative to the entire `text` value. The terminal does not infer it from `selectedRange` or `replacementRange`. It preserves the exact value in `terminal.compose` and the VT compose input, and rejects a missing, malformed, out-of-text, or grapheme-splitting range before changing status or queueing input. The VT screen preedit has the same required field and validation. `selectedRange` continues to describe selection and caret independently.
- `terminal.cursor.frame` is required and nullable. For a validated `screen` event, the cursor status publishes the exact `frame` (`null` or `{generation, raster, sequence}`) together with that event's cursor and `cursor.preedit` in one status update. A `state` event that updates the cursor clears `frame` to `null` because it does not identify rendered screen pixels. A state cursor may omit `frame` or set it to `null`; it cannot identify a non-null screen frame. An invalid frame uses the existing screen-input error path and leaves the previous cursor status unchanged.
- `screen.render` is required on each current screen event. `null` means the renderer did not produce a matching draw for that event; a non-null renderer object must carry exactly the screen event's frame. Its required fields are `frame`, `pixel`, `grid`, `font`, `underline`, `cursor` and `glyphs`. `pixel` identifies top-left BGRA8 premultiplied sRGB raster dimensions and stride; `grid` identifies integer rows, columns, origin and cell dimensions; `font` carries the actual family and metrics. `underline.positionFromBaseline` uses CoreText y-up units. Each glyph carries its row, column, cell width, positive CoreText `fontRuns` count, grapheme, effective opaque lowercase sRGB foreground/background, and nullable fractional top-left cell-local ink and underline rectangles. The cursor carries its nullable pixel rectangle, shape, visibility, focus, blend, color and border; its color is null for hidden, invisible or difference-blended cursors, otherwise it is the effective opaque lowercase sRGB color. The terminal publishes `terminal.cursor.render` as required nullable status alongside `frame`, cursor and preedit in the same status update. The terminal rejects a missing field, malformed value or mismatched frame before changing screen or cursor state. It passes a declared screen-message projection without the terminal-only `render` extension to `screenFromMessage` and `screenHash`. A state event cannot identify a rendered draw; when it updates cursor state it clears both `frame` and `render` to `null`, and refuses a non-null render value.
