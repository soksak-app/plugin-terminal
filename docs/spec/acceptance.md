# Terminal plugin acceptance

[한국어](acceptance.ko.md)

This plugin holds the criteria of terminal image regions. Core keeps the generic criteria of [surface composition](https://github.com/soksak-app/core/blob/main/docs/spec/surface-composition.md#acceptance).

- A terminal image preserves its logical text while resizing: narrowing reduces terminal columns and reflows long logical rows onto multiple screen rows; widening increases columns and reflows those rows back without truncation or permanent narrow wrapping.
- Terminal cell width and height are stable presentation metrics during layout; divider movement changes the surface and raster geometry, not the font or cell metrics, and native geometry changes do not animate.

- Each error that `terminal.session` shows reaches the surface error display when it appears: the view reports the text that `terminal.session` holds through `tab.error`, whose display writes it to the application log (core [plugins](https://github.com/soksak-app/core/blob/main/docs/spec/plugins.md)). The same text again, such as the refusal of each later `view` event without `background`, does not appear again and is not reported again. When an error of `terminal.session` resolves, the tab error display follows it: it shows the error of another source that `terminal.session` still shows, or `tab.error(null)` removes the error when `terminal.session` shows none. A failed `terminal.focus` press is reported once, with the text of `terminal.session`.
- A program in the terminal writes and reads the clipboard through OSC 52 requests, which the sidecar delivers as `clipboard.store` and `clipboard.query` events, as the setting `clipboard.program` admits: `deny` admits neither, `write` admits only a store, and `allow` admits both; the default is `write`, so a program copy reaches the clipboard and no program reads the clipboard without the person's setting. A store or query that the setting refuses is no input failure and shows no error: the view writes the event `plugin.terminal.clipboard.refused` with `operation` (`store` or `query`) and `policy`, and answers a refused query with `clipboard.reject` and the reason `program clipboard query denied by policy`. An admitted request that fails, such as an unsupported target, a missing clipboard capability or a failed write, reaches `terminal.session` and the surface error display. A value of `clipboard.program` other than the three is refused with `clipboard.program setting is invalid: <value>`. The person's own copy and paste do not depend on the setting.
- A primary pointer press on the terminal view runs the declared `terminal.focus` command through the shared exposure binder. The command transfers keyboard ownership to the native image region. The view prevents default DOM focus, reports a failed focus in `terminal.session` and through the surface error path, and removes the binding when the page is disposed. A separate view document does not depend on pointer bubbling to a card in the main document.
- Each report-bearing native input scope arrives as one region event `{type:'input', actions, preedit, errors, cids}`. The handler of these events is the `input` of `composition.create` (core [page API](https://github.com/soksak-app/core/blob/main/docs/spec/surface-composition.md#page-api)), which the terminal gives at the creation of its composition: each event reaches it in its dispatch, in order, from the attachment of the region, nothing holds an event, and the page registers no `on("input")` on the region. `cids` contains exactly one scope correlation identifier. The ordered `actions` are committed insert `{type:'insert', text, replacementRange, attributed}`, key `{type:'key', key, shift, alt, ctrl, text?}`, command `{type:'command', selector}`, or focus `{type:'focus', focused}` records. A key action has `text` only when `key` is `Char`, and then it is a string; other keys omit it. Focus `focused` is boolean. `errors` is an ordered list of `{reason}` records. The required strict `preedit` object contains `text`, `markedRange`, `selectedRange`, `replacementRange` and `attributed`; empty `text` clears preedit. An empty action list is valid for a compose-only report. Standalone `insertText` and `setMarkedText` callbacks each form one input scope; a keyDown with no reported callbacks produces no event. The VT `input` request is `{actions, preedit}` with the same ordered actions and final snapshot. Paste and `terminal.input` submit one insert action with the current strict preedit. The terminal validates the entire native event and every action before status or sidecar mutation, then attempts exactly one `input` request, passing `cids` as request correlation metadata rather than a body field. It applies the final snapshot to `terminal.compose` once. After the request attempt, it reports every valid event error in order, including when sending the request fails; a send failure is also reported, and event errors are not VT actions. Invalid events cause no status update or VT request. The `native-input` diagnostic entry's `input` projection contains exactly `{actions, preedit, errors}`; its event kind and `cids` are separate fields. The `terminal-input` entry contains the exact VT request body and its `cids`. It does not synthesize records for nested callbacks. The terminal does not consume the nested `insert`, `key`, `command` or intermediate `compose` callbacks separately and does not infer a compose transition from text or wait for another callback. The VT sidecar applies the actions and final preedit in one surface input command and does not present an intermediate compose-only frame from that transaction.
- `terminal.ime.trace` records bounded native-input and terminal-input entries only. It does not retain screen frames. When performance tracing is enabled, the existing `plugin.terminal.sidecar.event` trace records the received sidecar body, including screen cells, frame tuple, cursor/preedit and render metadata, subject to the event-size limit. Each accepted `screen` message writes the exact native frame tuple or `null` to the DEBUG `plugin.terminal.frame` event before asynchronous hash calculation, alongside message session, segment, sequence, dimensions and screen hash. The native frame tuple identifies the raster that produced the message; message sequence alone does not uniquely identify a native frame. A consumer joins the body to the accepted-frame marker by session, segment and message sequence, then requires the body and marker frame tuples to match. It rejects missing or truncated bodies and any matching `log.dropped`, `log.gated` or `log.pruned` loss record rather than borrowing state from a neighboring event. These records identify accepted terminal source state only and do not claim that a compositor or display presented the frame.
- Diagnostic builds expose `terminal.view.history`, which reads the current view document's `window.history.length`, and `terminal.view.frames`, which explicitly starts or stops the view document's content-frame observer. The observer is disabled by default and retains no frame history. Every successful `start` reply includes a fresh `sourceClock` sampled during that invocation from the same view document's `performance.timeOrigin` and `performance.now()`, plus `sourceResolutionMs: 1` as the fixed WebKit clock-resolution bound. Repeated `start` calls refresh the anchor without restarting observation. The bound is metadata, not a measured resolution. Each observed `plugin.terminal.view.content_frame` trace records the document root's content-box width and height after `ResizeObserver` and the next animation frame, with `resizeAtMs` and `frameTimeMs` on the document clock. The event describes a document size update and does not claim that the compositor displayed that size.
- The final preedit includes the required `markedRange` key: `null` when no text is marked, or `{location, length}` in UTF-16 code units relative to the entire `text` value. The terminal does not infer it from `selectedRange` or `replacementRange`. It preserves the exact value in `terminal.compose` and the VT input request, and rejects a missing, malformed, out-of-text, or grapheme-splitting range before changing status or queueing input. The VT screen preedit has the same required field and validation. `selectedRange` continues to describe selection and caret independently.
- `terminal.cursor.frame` is required and nullable. For a validated `screen` event, the cursor status publishes the exact `frame` (`null` or `{generation, raster, sequence}`) together with that event's cursor and `cursor.preedit` in one status update. A `state` event that updates the cursor clears `frame` to `null` because it does not identify rendered screen pixels. A state cursor may omit `frame` or set it to `null`; it cannot identify a non-null screen frame. An invalid frame uses the existing screen-input error path and leaves the previous cursor status unchanged.
- Each current `screen` message requires the `cursor.caret` key. Its value is `null` when no raster for the current target has been accepted (including no image, sequence zero, or a dirty/future target), or `{row, col}` for a clean sent frame. The non-negative integer coordinates identify the visible input-method caret in the screen grid and come from the same `RenderLayout` as that frame. Raw `cursor.row` and `cursor.col` retain their engine and replay/hash meaning; the terminal does not substitute them for `caret`. The terminal publishes `terminal.cursor.caret` with the same screen event as the cursor, frame and render metadata. A state event clears `caret` to `null` and does not move the native caret. Missing, malformed or out-of-grid non-null caret coordinates reject the screen event before screen or cursor status changes. A null caret does not move the native caret.
- `screen.render` is required on each current screen event. `null` means the renderer did not produce a matching draw for that event; a non-null renderer object must carry exactly the screen event's frame. Its required fields are `frame`, `pixel`, `grid`, `font`, `underline`, `cursor` and `glyphs`. `pixel` identifies top-left BGRA8 premultiplied sRGB raster dimensions and stride; `grid` identifies integer rows, columns, origin and cell dimensions; `font` carries the actual family and metrics. `underline.positionFromBaseline` uses CoreText y-up units. Each glyph carries its row, column, cell width, positive CoreText `fontRuns` count, grapheme, effective opaque lowercase sRGB foreground/background, and nullable fractional top-left leading-cell-local ink and underline rectangles. These are raw CTFont/CTLine bounds after subtracting the leading cell origin, not cell-clipped geometry; x and y may be negative and bounds may extend past the cell or glyph span. Coordinates must be finite and rectangle width/height must be positive. Consumers may intersect the geometry with the raster when measuring pixels but must not rewrite the declared bounds. The cursor is drawn only when `visible` and `blinkVisible` are true and shape is not `hidden`; its rectangle is non-null exactly in those frames. A drawn normal cursor has its effective opaque lowercase sRGB color; a difference-blended cursor has null color. An undrawn cursor has a null rectangle and color, including a visible normal cursor whose blink is off. The terminal publishes `terminal.cursor.render` as required nullable status alongside `frame`, cursor and preedit in the same status update. The terminal rejects a missing field, malformed value or mismatched frame before changing screen or cursor state. It passes a declared screen-message projection without the terminal-only `render` extension to `screenFromMessage` and `screenHash`. A state event cannot identify a rendered draw; when it updates cursor state it clears both `frame` and `render` to `null`, and refuses a non-null render value.
- A `screen` message is the full form (`base: true`) or a change form (`base: false`) of core `docs/spec/persistent-services.md#screen-message`. The view applies each message with `applyScreenMessage` to the result of the message it applied before, hashes the full screen that results, and replaces in `terminal.screen` only the rows that a change carries. It sends `screen.read` after it opens or reattaches a session and after it refuses a change; until the full form that answers the read arrives, it refuses each change and writes `plugin.terminal.screen.refused` with its `number` and `previous`. A change that does not follow the held screen is an error of the source `screen`. `terminal.screen.read` resolves with the full form that answers its read.
- The sidecar sends no `screen` message for a frame and answers `screen.read` with the full form. After a drawn frame it sends `{event: "view", frame, rows, cols, cursor, scrollback, background}` when the grid, the cursor, the scrollback or the default background of that frame changes. The view checks the whole event, then publishes the cursor with `frame`, `caret` and a null `render` in `terminal.cursor`, moves the input-method caret to `caret`, publishes `scrollback` in `terminal.session`, and paints the scrollbar track and the padding strips with `background`, which no other message paints. A refused event changes no status and is an error of the source `view` until the next valid `view` event.
- The scrollbar track is shown while the terminal keeps history (`scrollback.history` above 0). The view places the thumb in CSS relative to the track from `rows` of `terminal.session` and `scrollback {offset, history}`, and reads no rectangle for the placement: the height of the thumb is `max(16px, P%)` with P = 100 × rows / (rows + history), and its top is `min(calc(100% - max(16px, P%)), Q%)` with Q = 100 × (history − offset) / (rows + history). The view sets these styles again when `rows` (from the `state` event), `offset` or `history` changes; a change of the size of the track moves the thumb with the track, so at `offset` 0 the thumb ends at the bottom of the track. A drag of the thumb runs `terminal.scrollback.set` with the offset under the pointer: the view compares `clientY` with the `getBoundingClientRect()` of the thumb at the press and of the track at each move, which share the CSS pixels of the view document, because the root view of the surface keeps page zoom 1 and the view sets no CSS `zoom` (the terminal follows the text size with its font size).
- The scrollbar shows the history of the screen in view, and the alternate screen shows none. The sidecar reports `scrollback` of the active screen; the alternate screen keeps no history, so while a program holds it `scrollback` is `{offset: 0, history: 0}` and the track is hidden. The wheel stays a `scroll` operation, which the sidecar writes to the program as mouse wheel reports or, under alternate scroll (mode 1007), as cursor keys, so a program that scrolls its own content, such as an agent client, scrolls with the wheel. The sidecar keeps the primary history while the alternate screen is active, and when the program leaves it the track returns with the thumb at the bottom. Reasons: on the alternate screen a scrollbar could only show a thumb as long as the track or the primary history, and the person can scroll neither there, because the wheel belongs to the program, the engine draws only the active screen, and no protocol tells the terminal the scroll position of a program; a control that scrolls nothing is not shown. Other terminals decide the same way or show an inert scrollbar: kitty shows its scrollbar only on the main screen, the terminal of xterm.js has no scrollback in the alternate buffer and sends the wheel as cursor keys, Ghostty reports a scrollbar whose length is the whole screen for a screen without scrollback, and WezTerm, whose scrollbar is off by default, fills the track with the thumb. iTerm2 draws the alternate screen over its retained scrollback, so its scrollbar scrolls the primary history; this engine draws the active screen only, so the view does not follow it. The track is an overlay at the right edge of the view, so hiding it changes neither the columns nor the rows of the terminal.
- A wait of the view for a reply of the sidecar has no time limit (core [calls across a boundary](https://github.com/soksak-app/core/blob/main/docs/spec/plugin-processes.md), rule 3). The acknowledgement of `screen.watch`, the full form that answers `screen.read` and the answer of `pty.pending` each end by that reply, by a failed send, by the `sidecar-failure` of the surface, by a `connection` event, by the close of the view, or by the next request of the same kind for `screen.watch` and `pty.pending`. A failure ends the wait with `the sidecar ended before it answered: <reason>`, a connection event with `the sidecar connection changed before it answered`, and the close with an `AbortError`; the view sets no timer for a reply. The sidecar answers `pty.pending` requests in their order, so the view drops the answer of each request that a later request replaced; a request whose send failed has no answer to drop, and a `sidecar-failure` or a connection event leaves none.
- `terminal.screen.rows {from, count}` refuses a `from` below 0, or a `count` outside 1 to 200, before it sends a request. It sends `screen.read {from, count}` with one correlation identifier of its own, and the sidecar names that identifier in its answer. The `screen.rows` event of the range resolves the read with the rows and the plain text of each row. The refusal `{error, reason}` of a range outside the retained rows rejects the read with `terminal.screen.rows: <error>: <reason>` and sets no error of `terminal.session`. Another answer under that identifier rejects the read as mismatched. An answer that names no waiting read is the record `plugin.terminal.screen.rows.unmatched`. A waiting read also ends as the other waits for a reply of the sidecar end.
- `terminal.state` is `{state, source, sequence, exit}` of core [terminal state](https://github.com/soksak-app/core/blob/main/docs/spec/terminal-state.md): `{state: null, source: null, sequence: 0, exit: null}` until the first read, then the reply `shell.state.current` of `shell.state.read`, which the view sends once each time the session opens or is attached again, and then each `shell.state` change event. A session with another identifier starts again from the value before the first read. An event or a reply of another form is reported through the session error as `terminal input failed: invalid terminal state from sidecar: <member>: <body>`, and the value stays. The tests run the copy of the shared cases `docs/spec/cases/terminal-state/osc133.json` of core, `test/fixtures/terminal-state-osc133.json`.
- `terminal.activity` is the core activity level of core [terminal state](https://github.com/soksak-app/core/blob/main/docs/spec/terminal-state.md#activity), derived from `terminal.state`: `idle`, `running`, `failed` for an exited command with a nonzero exit code, or null; it notifies only when the level changes.
- `terminal.messages` is `{folder, registration}` of the messages folder of core [messaging](https://github.com/soksak-app/core/blob/main/docs/spec/messaging.md#folder-of-a-terminal): the page sends `messages.register` with `<root>/.soksak/messages/<surface>` of the project of its start values and one correlation identifier once its sidecar port is connected and after each reconnection, and sends nothing without a project. The status is null before the reply, without a project, while the sidecar connection is down and after `registration.closed` of its registration; a refused or closed registration is shown through the tab error display (`tab.error`), which writes it to the application log as `terminal.messages: <error>: <reason>`. `terminal.messages.read` and `terminal.messages.wait` send `messages.read` and `messages.wait` with the members `after` and `registration` that are present and one correlation identifier, answer the body of the reply that names it, reject a refusal with `terminal.messages.read: <error>: <reason>` (or `.wait`), and refuse another member before any request; the sidecar checks the values. The end of the sidecar connection rejects each waiting request with `terminal.messages.read: the sidecar connection ended` (or `.wait`), and the close of the view with `the view closed`. A reply that names no waiting request is the record `plugin.terminal.messages.unmatched`; `file.changed` needs no page action.
