# Terminal plugin acceptance

[한국어](acceptance.ko.md)

This plugin holds the criteria of terminal image regions. Core keeps the generic criteria of [surface composition](https://github.com/soksak-app/core/blob/main/docs/spec/surface-composition.md#acceptance).

- A terminal image preserves its logical text while resizing: narrowing reduces terminal columns and reflows long logical rows onto multiple screen rows; widening increases columns and reflows those rows back without truncation or permanent narrow wrapping.
- Terminal cell width and height are stable presentation metrics during layout; divider movement changes the surface and raster geometry, not the font or cell metrics, and native geometry changes do not animate.

- A primary pointer press on the terminal view runs the declared `terminal.focus` command through the shared exposure binder. The command transfers keyboard ownership to the native image region. The view prevents default DOM focus, reports a failed focus in `terminal.session` and through the surface error path, and removes the binding when the page is disposed. A separate view document does not depend on pointer bubbling to a card in the main document.
- Each report-bearing native input scope arrives as one region event `{type:'input', actions, preedit, errors, cids}`. `cids` contains exactly one scope correlation identifier. The ordered `actions` are committed insert `{type:'insert', text, replacementRange, attributed}`, key `{type:'key', key, shift, alt, ctrl, text?}`, command `{type:'command', selector}`, or focus `{type:'focus', focused}` records. A key action has `text` only when `key` is `Char`, and then it is a string; other keys omit it. Focus `focused` is boolean. `errors` is an ordered list of `{reason}` records. The required strict `preedit` object contains `text`, `markedRange`, `selectedRange`, `replacementRange` and `attributed`; empty `text` clears preedit. An empty action list is valid for a compose-only report. Standalone `insertText` and `setMarkedText` callbacks each form one input scope; a keyDown with no reported callbacks produces no event. The VT `input` request is `{actions, preedit}` with the same ordered actions and final snapshot. Paste and `terminal.input` submit one insert action with the current strict preedit. The terminal validates the entire native event and every action before status or sidecar mutation, then attempts exactly one `input` request, passing `cids` as request correlation metadata rather than a body field. It applies the final snapshot to `terminal.compose` once. After the request attempt, it reports every valid event error in order, including when sending the request fails; a send failure is also reported, and event errors are not VT actions. Invalid events cause no status update or VT request. The `native-input` diagnostic entry's `input` projection contains exactly `{actions, preedit, errors}`; its event kind and `cids` are separate fields. The `terminal-input` entry contains the exact VT request body and its `cids`. It does not synthesize records for nested callbacks. The terminal does not consume the nested `insert`, `key`, `command` or intermediate `compose` callbacks separately and does not infer a compose transition from text or wait for another callback. The VT sidecar applies the actions and final preedit in one surface input command and does not present an intermediate compose-only frame from that transaction.
- `terminal.ime.trace` records bounded native-input and terminal-input entries only. It does not retain screen frames. When performance tracing is enabled, the existing `plugin.terminal.sidecar.event` trace records the received sidecar body, including screen cells, frame tuple, cursor/preedit and render metadata, subject to the event-size limit. The existing DEBUG `plugin.terminal.frame` event records the accepted frame's session, segment, sequence and screen hash after validation. A consumer joins the body to the accepted-frame marker by session, segment and message sequence, then uses the body's frame tuple; it rejects missing or truncated bodies and any matching `log.dropped`, `log.gated` or `log.pruned` loss record rather than borrowing state from a neighboring event. These records identify accepted terminal source state only and do not claim that a compositor or display presented the frame.
- The final preedit includes the required `markedRange` key: `null` when no text is marked, or `{location, length}` in UTF-16 code units relative to the entire `text` value. The terminal does not infer it from `selectedRange` or `replacementRange`. It preserves the exact value in `terminal.compose` and the VT input request, and rejects a missing, malformed, out-of-text, or grapheme-splitting range before changing status or queueing input. The VT screen preedit has the same required field and validation. `selectedRange` continues to describe selection and caret independently.
- `terminal.cursor.frame` is required and nullable. For a validated `screen` event, the cursor status publishes the exact `frame` (`null` or `{generation, raster, sequence}`) together with that event's cursor and `cursor.preedit` in one status update. A `state` event that updates the cursor clears `frame` to `null` because it does not identify rendered screen pixels. A state cursor may omit `frame` or set it to `null`; it cannot identify a non-null screen frame. An invalid frame uses the existing screen-input error path and leaves the previous cursor status unchanged.
- Each current `screen` message requires the `cursor.caret` key. Its value is `null` when no raster for the current target has been accepted (including no image, sequence zero, or a dirty/future target), or `{row, col}` for a clean sent frame. The non-negative integer coordinates identify the visible input-method caret in the screen grid and come from the same `RenderLayout` as that frame. Raw `cursor.row` and `cursor.col` retain their engine and replay/hash meaning; the terminal does not substitute them for `caret`. The terminal publishes `terminal.cursor.caret` with the same screen event as the cursor, frame and render metadata. A state event clears `caret` to `null` and does not move the native caret. Missing, malformed or out-of-grid non-null caret coordinates reject the screen event before screen or cursor status changes. A null caret does not move the native caret.
- `screen.render` is required on each current screen event. `null` means the renderer did not produce a matching draw for that event; a non-null renderer object must carry exactly the screen event's frame. Its required fields are `frame`, `pixel`, `grid`, `font`, `underline`, `cursor` and `glyphs`. `pixel` identifies top-left BGRA8 premultiplied sRGB raster dimensions and stride; `grid` identifies integer rows, columns, origin and cell dimensions; `font` carries the actual family and metrics. `underline.positionFromBaseline` uses CoreText y-up units. Each glyph carries its row, column, cell width, positive CoreText `fontRuns` count, grapheme, effective opaque lowercase sRGB foreground/background, and nullable fractional top-left leading-cell-local ink and underline rectangles. These are raw CTFont/CTLine bounds after subtracting the leading cell origin, not cell-clipped geometry; x and y may be negative and bounds may extend past the cell or glyph span. Coordinates must be finite and rectangle width/height must be positive. Consumers may intersect the geometry with the raster when measuring pixels but must not rewrite the declared bounds. The cursor is drawn only when `visible` and `blinkVisible` are true and shape is not `hidden`; its rectangle is non-null exactly in those frames. A drawn normal cursor has its effective opaque lowercase sRGB color; a difference-blended cursor has null color. An undrawn cursor has a null rectangle and color, including a visible normal cursor whose blink is off. The terminal publishes `terminal.cursor.render` as required nullable status alongside `frame`, cursor and preedit in the same status update. The terminal rejects a missing field, malformed value or mismatched frame before changing screen or cursor state. It passes a declared screen-message projection without the terminal-only `render` extension to `screenFromMessage` and `screenHash`. A state event cannot identify a rendered draw; when it updates cursor state it clears both `frame` and `render` to `null`, and refuses a non-null render value.
